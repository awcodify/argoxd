A k9s-style terminal UI for Argo CD

argoxd helps Kubernetes and platform engineers operate Argo CD from the terminal: browse applications and resources, inspect YAML, diffs, logs, and events, then sync, refresh, restart, delete, or roll back with confirmation.

It is open-source software for GitOps operations, available for macOS, Linux, and Windows. Connect with kubeconfig or directly to the Argo CD API.

◆ features

Day-to-day Argo CD, at k9s speed.

◆k9s-style navigation

List Applications, AppProjects and Clusters. Press Enter to drill into an Application's resources, Esc to go back. Command bar with :, search with /.

⎈Every cluster, every instance

Connect with your kubeconfig, or to the Argo CD API with --source api and a token. Hop between clusters with :ctx and between Argo CD instances with :ns, without restarting.

▣Resource cards

Deployments → ReplicaSets → Pods nested under their owners. Open live YAML (Y), yank names or text (y), diff against desired state (d), Pod logs (l) and events (e).

●Safe bulk actions

Mark rows with Space, then sync, refresh, restart or delete them together, or press a on a card for any Argo CD resource action, like a Rollout's promote. Every action shows exactly what it will touch and waits for confirmation first. Run with --read-only to block them all.

≡Logs that follow

l on a Deployment, StatefulSet or Job streams all its Pods at once, each line tagged with its Pod. Follow with f, switch container with c or Pod with p, filter with /.

⑂App of apps & ApplicationSets

Enter on a child Application opens it, Esc returns to the parent, breadcrumbs show the path. :appset lists ApplicationSets with their generators and problems, and Enter shows what each generated.

◐Pulse overview

:pulse draws health and sync as bars, counts auto-sync policies, and lists the Applications that need attention — worst first, with the reasons.

✂Prune & orphan insight

See which resources a sync with prune would delete and which ones no Application manages. Check conditions, sync details (i) and history, then roll back with h.

◆ safe on production

argoxd can sync and delete, so it is built to make that hard to do by accident.

?Every action asks

Sync, refresh, rollback, terminate, restart and delete show the exact Applications or resources they will touch, and wait for Enter.

⊘Read-only mode

--read-only or readOnly: true blocks every action that changes something, and the header shows [READ-ONLY].

⎈Your own identity

argoxd acts as your kubeconfig user or Argo CD token. It cannot do anything your RBAC does not already allow.

○No agent, no install

Nothing runs in the cluster. It is a single binary that talks to the Kubernetes or Argo CD API you already use.

Need a read-only identity for your team? The README has a ready-made Role and the full permission list.

◆ frequently asked questions

What is argoxd?

argoxd is an open-source terminal user interface for Argo CD. It brings a resource-focused, k9s-style workflow to GitOps operations, so you can inspect and act on Argo CD Applications and their Kubernetes resources without leaving the terminal.

How does argoxd connect to Argo CD?

By default, it uses your active kubeconfig context and looks for Argo CD in the argocd namespace. You can instead use the Argo CD API with --source api, a server URL, and a token.

Can I try argoxd without a Kubernetes cluster or Argo CD?

Yes. Run argoxd --demo to explore sample applications, resources, YAML, diffs, and logs. It needs no cluster or credentials, and its actions change only in-memory sample data.

Which operating systems support argoxd?

argoxd supports macOS, Linux, and Windows. Install with Homebrew on macOS or Linux, with go install, or by downloading a prebuilt binary from GitHub Releases.

Is it safe to point argoxd at production?

Yes, with care. Every action shows what it will touch and waits for confirmation, --read-only blocks all of them, and argoxd can only do what your own kubeconfig user or Argo CD token is allowed to do. Nothing is installed in the cluster.

What permissions does argoxd need?

To browse, it needs to list Argo CD's Applications, AppProjects and cluster Secrets. Logs, events and workloads need the matching read access, and each action needs its own write permission. The README lists them all and includes a ready-made read-only Role.

Does argoxd work with several Argo CD instances?

Yes. :ctx switches the kubeconfig context and :ns switches the namespace Argo CD runs in, both without restarting. Marks are cleared on every switch, so an action never carries over to another instance.

Can I use argoxd without access to the cluster?

Yes. With --source api, a server URL and a token, argoxd talks only to the Argo CD API. That mode also adds diffs, orphaned resources and opening apps in the web UI.
